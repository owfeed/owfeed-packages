# Пакеты сообщества owfeed

*[English version](README.md)*

Фид пакетов OpenWrt для обеих релизных линий: apk для 25.12 и новее, opkg для 24.10 и старее.
Собирает и публикует его [owfeed](https://github.com/owfeed/owfeed).

- Фид раздаёт чужие пакеты байт в байт, как их собрали авторы.
- Роутер подписывается одной командой. Скрипт сам определяет пакетный менеджер, архитектуру и релиз роутера.
- Фид подписывает индекс. Пакеты он не подписывает.
- Установив ключ фида, вы доверяете ему для любого имени пакета. Прочитайте раздел [Прежде чем ставить ключ](#прежде-чем-ставить-ключ).

## Быстрый старт

1. Скачайте скрипт подписки, прочитайте его, запустите. Он работает от root.

   ```sh
   wget -O subscribe.sh https://repo.owfeed.org/subscribe.sh && less subscribe.sh && sh subscribe.sh
   ```

   Если `wget` падает на HTTPS, в образе нет двух пакетов. В стоковых образах они есть, в
   собственных сборках может не быть. Поставьте их и повторите шаг 1: `apk add ca-bundle libustream-mbedtls`.
   На 24.10 вместо `apk add` используйте `opkg install`.

2. Ставьте пакет по имени: `apk add <name>` на 25.12, `opkg install <name>` на 24.10. Сам скрипт
   пакетов не ставит.

Однострочник пропускает шаг с чтением:

```sh
wget -qO- https://repo.owfeed.org/subscribe.sh | sh
```

## Что делает скрипт подписки

Он работает на любой из двух релизных линий.

1. Определяет пакетный менеджер, архитектуру и релиз роутера.
2. На 25.12 ставит `ca-bundle` и `libustream-mbedtls`, без них не работает HTTPS.
3. Ставит ключ.
4. Добавляет репозиторий.
5. Сохраняет ключ и репозиторий при обновлении прошивки. Для этого он пишет
   `/lib/upgrade/keep.d/owfeed-packages`, тот же файл, что и команды ниже.

- Повторный запуск ничего не меняет дважды. На 24.10 скрипт удаляет свою старую строку из
  `/etc/opkg/customfeeds.conf`, прежде чем добавить новую.
- Пакетов он не ставит. После него запустите `apk add <name>` или `opkg install <name>`.
- Скрипт генерирует `owfeed index` из того же конфига, по которому разложен фид. Поэтому в нём не
  может оказаться URL, которого фид не отдаёт. Всё равно прочитайте его: он работает от root.

## Руками на OpenWrt 25.12 и новее

```sh
# HTTPS needs these. Stock images have them; custom builds may not.
apk add ca-bundle libustream-mbedtls

wget https://repo.owfeed.org/owfeed-packages.pem -O /etc/apk/keys/owfeed-packages.pem
echo "https://repo.owfeed.org/releases/25.12/$(cat /etc/apk/arch)/packages.adb" > /etc/apk/repositories.d/owfeed-packages.list

# Keep the key and the repository across a firmware upgrade.
mkdir -p /lib/upgrade/keep.d
printf '%s\n' /etc/apk/keys/owfeed-packages.pem /etc/apk/repositories.d/owfeed-packages.list > /lib/upgrade/keep.d/owfeed-packages

apk update && apk add luci-theme-footstrap
```

`luci-theme-footstrap` — один из пакетов, которые раздаёт фид. Подставьте имя нужного вам пакета.

## Руками на OpenWrt 24.10 и старее

```sh
# The key file's NAME is its id — opkg looks it up by that.
mkdir -p /etc/opkg/keys
wget https://repo.owfeed.org/9040356b214084da -O /etc/opkg/keys/9040356b214084da

echo "src/gz owfeed-packages https://repo.owfeed.org/releases/24.10/$(. /etc/openwrt_release; echo $DISTRIB_ARCH)" >> /etc/opkg/customfeeds.conf

# Keep the key and the repository across a firmware upgrade.
mkdir -p /lib/upgrade/keep.d
printf '%s\n' /etc/opkg/keys/9040356b214084da /etc/opkg/customfeeds.conf > /lib/upgrade/keep.d/owfeed-packages

opkg update && opkg install luci-theme-footstrap
```

- Выполните этот блок один раз. `>>` дописывает в конец файла, и второй запуск добавит вторую
  строку `src/gz owfeed-packages`. Скрипт подписки сначала удаляет старую строку, поэтому его можно
  запускать повторно.
- `luci-theme-footstrap` — один из пакетов, которые раздаёт фид. Подставьте имя нужного вам пакета.

## Ставьте по имени из индекса

Добавьте репозиторий и ставьте пакет по имени. Файл пакета напрямую не ставьте.

- На 25.12 `apk add ./file.apk` записывает в `/etc/apk/world` привязку к хешу содержимого пакета.
  Этот файл переживает sysupgrade, и пакет больше никогда не обновится из этого фида.
- `apk add ./file.apk` и *Upload Package* в LuCI требуют `--allow-untrusted` для пакетов отсюда.
- Установка по имени из индекса — документированный способ и единственный, при котором пакет обновляется.

## Attended Sysupgrade теряет эти пакеты

Attended Sysupgrade не переносит эти пакеты в новую прошивку.

- `owut` не передаёт сторонние репозитории.
- `repository_allow_list` на сервере sysupgrade по умолчанию пуст, а пустой список запрещает всё.

## Прежде чем ставить ключ

Ставьте ключ, потому что доверяете тому, кто его публикует. Страница, которая велит его поставить, —
не причина.

- Ключу в `/etc/apk/keys` доверяют для **любого имени пакета**, а не только для тех, что раздаёт этот фид.
- Он подтверждает индекс, в котором заявлено любое имя. Поэтому этот фид или любой, у кого оказался
  скомпрометированный ключ, может предложить более высокую версию базового пакета, например
  `dropbear` или `base-files`, и выиграть при разрешении зависимостей.
- В apk нет отзыва: ни CRL, ни срока действия, ни способа объявить ключ мёртвым.

## Проверьте установленный ключ

Сравните ключ на роутере с копией, полученной другим путём. Одинаковый хеш — один и тот же файл.

| Релизная линия | Файл ключа на роутере | Где опубликован |
|---|---|---|
| 25.12 и новее | `/etc/apk/keys/owfeed-packages.pem` | `https://repo.owfeed.org/owfeed-packages.pem` |
| 24.10 и старее | `/etc/opkg/keys/9040356b214084da` | `https://repo.owfeed.org/9040356b214084da` |

1. На роутере выведите хеш файла ключа:

   ```sh
   sha256sum /etc/apk/keys/owfeed-packages.pem
   ```

2. На другой машине, из другой сети, скачайте опубликованный ключ и выведите его хеш:

   ```sh
   curl -s https://repo.owfeed.org/owfeed-packages.pem | sha256sum
   ```

3. Сравните два хеша. Для ключа opkg возьмите путь и URL из таблицы.

- Id ключа opkg — `9040356b214084da`. Имя файла ключа и есть этот id.
- В этом репозитории нет копии публичного ключа самого фида. Он опубликован только в корне фида,
  поэтому сверка — это второе скачивание по пути, которому вы доверяете.

## Что означает подпись этого фида

**Этот фид подписывает индекс. Пакеты он не подписывает.**

Подпись означает одно: это те байты, которые опубликовал этот фид, и пришли они от автора, чей ключ
здесь запинен. Это утверждение о канале и о происхождении. О содержимом, качестве, безопасности,
законности или пригодности оно ничего не говорит. Не читайте его так.

Ничего в этом репозитории не пересобирается и не меняется. Вы ставите собственный файл автора, байт в байт.

### Что фид проверяет

- Релиз существует в репозитории и под тегом, которые запинены в `packages/<name>/upstream.sh`.
- Отделённая подпись автора над ним сходится с публичным ключом, запиненным в [`keys/`](keys/), а
  манифест называет тот репозиторий и тот тег, откуда он якобы пришёл.
- Байты совпадают с записанным здесь `sha256`, то есть не менялись с тех пор, как на них посмотрел человек.
- Получившееся дерево внутренне согласовано (`owfeed doctor`) и ставится на стоковый образ OpenWrt
  без `--allow-untrusted` (`owfeed smoke`).

### Чего фид не проверяет

- Что делает код. Ни ревью, ни аудита, ни анализа исходников или бинарника.
- Безопасен ли он. Никакой оценки безопасности пакета, его зависимостей или того, что он делает после запуска.
- Работает ли он и годится ли для чего-нибудь. `smoke` доказывает, что пакет ставится. О том,
  делает ли он то, что обещает автор, он ничего не говорит.
- Законен ли он там, где вы находитесь. Программа, законная в одной стране, бывает незаконна в
  другой. Фид не оценивает ни одну юрисдикцию, включая вашу.
- Правдивы ли заявленные лицензия, описание и метаданные. Это утверждения автора, переданные без изменений.

<details>
<summary>Почему фид подписывает индекс, а не пакеты</summary>

Это различие и есть всё, что утверждает подпись. Подпись легко прочитать как более широкое
утверждение, чем она есть.

- apk берёт доверие из индекса. Индекс подписан, и apk сверяет каждый пакет с записанным в нём
  хешем. Подпись индекса — то, что вообще делает фид устанавливаемым.
- Индекс, описывающий всё, что несёт фид, может выпустить только этот фид. Ключи авторов подписать
  его не могут, поэтому фид не может его не подписывать.
- Подписать ещё и каждый пакет значило бы поставить подпись этого фида внутрь файла, который собрал
  кто-то другой. Это утверждение об артефакте. Фид делает утверждения только о канале, по которому
  тот пришёл. Он не писал эти пакеты и не проводит их ревью.
- Пакет, который пришёл с подписью автора, сохраняет её. Блоки подписей apk дополняют друг друга, и
  здесь ничего их не срезает. Вы ставите файл автора, доставленный по подписанному каналу.
- Индексы подписывают два ключа, потому что каждый пакетный менеджер проверяет только свою схему:
  apk проверяет EC prime256v1, opkg проверяет usign.
- Требование `--allow-untrusted` для `apk add ./file.apk` и *Upload Package* ставит этот фид в то же
  положение, что и сам OpenWrt. Его собственные пакеты 25.12 по отдельности не подписаны, поэтому
  этот путь и так требует флага для всего в официальных фидах. Установку по имени это не затрагивает.

</details>

### Всё здесь используется на ваш страх и риск

Пакеты — чужие программы, они раздаются как есть, без каких-либо гарантий. За них отвечает их автор.
Вопросы, сообщения об ошибках и жалобы на пакет отправляйте его автору. `apk info <name>` на роутере
показывает репозиторий автора.

<details>
<summary>Полные условия</summary>

- Фид не писал ни одного из этих пакетов и не проводит их ревью. О том, что делает пакет, он знает
  только то, что заявляет автор.
- Никаких гарантий: те же условия, что уже записаны в собственной лицензии каждого пакета.
- Ответственность за пакет целиком лежит на его авторе: за содержимое, поведение, безопасность,
  законность и правдивость всего, что он о себе заявляет.
- Репозиторий автора указан в метаданных пакета. Вопросы, сообщения об ошибках и жалобы идут автору,
  а не сюда.
- Поставить пакет из этого фида значит запустить программу третьей стороны, которую не проверяли ни
  вы, ни этот фид. Это решение ваше, и последствия тоже ваши.
- Если вы считаете, что что-то здесь незаконно или нарушает ваши права, куда писать, сказано в
  [SECURITY_ru.md](SECURITY_ru.md). Такое обращение исполняется без споров.

</details>

## Как фид остаётся свежим

Обновления предлагает плановый job. CI проверяет каждое на настоящем образе OpenWrt, прежде чем оно
попадёт в `main`.

1. Раз в несколько часов job спрашивает у каждого апстрима его последний релиз.
2. Когда появляется новый, job пушит ветку с новой версией и её контрольными суммами. Суммы он
   пересчитывает по байтам, которые отдал релиз. Больше в ветке ничего нет.
3. CI собирает фид, индексирует его, проверяет и ставит на настоящий образ OpenWrt.
4. Ветка попадает в `main` автоматически или через pull request, как показывает таблица.

| Обновление | Как доезжает |
|---|---|
| Апстрим публикует отделённую подпись, у пакета `AUTO_MERGE="yes"` | автоматически, когда проверки пройдены |
| Новый пакет | pull request, ждёт мейнтейнера |
| Релиз без подписи | pull request, ждёт мейнтейнера |
| Мажорное обновление версии | pull request, ждёт мейнтейнера |
| Третье обновление одного пакета за сутки | pull request, ждёт мейнтейнера |
| Диф затрагивает больше одного `packages/<name>/upstream.sh` | pull request, ждёт мейнтейнера |

- Автоматическому обновлению человек не нужен. Следующий прогон переводит `main` на ветку
  fast-forward'ом, когда на этом самом коммите зелёные `check / build` и `check / check`.
- `tools/land-updates.sh` отказывается пушить, если они не зелёные. Контекст без единого прогона
  считается отказом. Проверки никогда не пропускаются.

<details>
<summary>Почему job предлагает, а не публикует</summary>

- Представьте job, который скачивает всё, что апстрим опубликовал с прошлого прогона, и подписывает
  ключом этого фида. Он передал бы полномочия этого ключа каждому апстриму.
- Пины контрольных сумм тогда стали бы украшением. Пересчитанные по тому, что пришло, они ничего бы
  не удостоверяли.
- Отделённая подпись рядом с артефактом апстрима — свидетельство происхождения от кого-то, кроме
  этого фида. Поэтому такой пакет может выставить `AUTO_MERGE="yes"`.
- Пакет, которого фид никогда не раздавал, приходит с ключом, который фид никогда не пинил. Это
  изменение в `keys/`, а туда ничего не попадает без присмотра.

</details>

## Чьи это пакеты

Каждый пакет заявляет свою лицензию и свой апстрим. Оба значения попадают в индекс и в `apk info` на
роутере, поэтому пользователь всегда может узнать, чью программу он поставил.

- Если пакет под копилефтной лицензией, его исходники отдаёт этот фид, в
  [`/sources/`](https://repo.owfeed.org/sources/index.txt).
- Это тот же источник, что и у бинарника, а именно этого GPLv2 §3 требует от всякого, кто его распространяет.
- Копилефтный пакет без исходников в дереве валит публикацию. Это гейт, он срабатывает на каждой публикации.
- Чтобы распространять чужую работу, мало лицензии, которая это разрешает.
  [LEGAL_ru.md](LEGAL_ru.md) записывает, что фид прочитал и что решил.
  *([English](LEGAL.md))*

## Добавить пакет

Пакет здесь — файл со значениями: версия, её контрольные суммы, каким ключом он подписан. Своего
скрипта у пакета нет.

- Публикуете впервые? Начните с [кукбука](https://owfeed.org/cookbook/ru/). Он описывает сборку и
  подпись пакета: это нужно сделать до того, как фид сможет его раздавать.
  *([English](https://owfeed.org/cookbook/))*
- [CONTRIBUTING_ru.md](CONTRIBUTING_ru.md): как добавить пакет, обновить его и дать ему обновляться самому.
  *([English](CONTRIBUTING.md))*
- [RUNBOOK_ru.md](RUNBOOK_ru.md): что и когда запускается и что делать, когда что-то красное.
  *([English](RUNBOOK.md))*
- Pull request'ы гоняют весь конвейер с одноразовым ключом, поэтому форк и близко не подходит к
  ключу самого фида.

<details>
<summary>Место этого фида рядом с owlab и owfeed</summary>

Этот фид — один конец более длинного жизненного цикла.

| Проект | Роль |
|---|---|
| [owlab](https://github.com/owfeed/owlab) | разрабатывает пакет и доказывает, что он работает |
| [owfeed](https://github.com/owfeed/owfeed) | подписывает и индексирует его |
| этот репозиторий | решает, чьим ключам доверять, и отдаёт результат роутерам |

[ECOSYSTEM.md](https://github.com/owfeed/owfeed/blob/main/docs/ECOSYSTEM.md) записывает границу
между тремя проектами, в том числе почему здесь никогда ничего не собирается.
[STATUS.md](STATUS.md) говорит, сколько из стороны этого фида уже есть и что ещё открыто.

</details>
